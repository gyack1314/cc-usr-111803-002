# 交易重量与分省表来源约定

normal.json 按顺序接收两份原文。conflict.json 的第二份与第一份使用相同资料身份和版次，但内容不同，账本应拒绝冲突。kind、id 和 revision 是来源声明，不能单独证明跨来源业务归属。

统计周内产地目录可能连续修改代码，日期范围按每条公告自己的 `effective_on` 判断。原始省表的 HB-01 行不随目录回写；11 月 11 日后解析为 HB-02，11 月 13 日后还需继续解析至 HB-03。省级均重仍按原始七日记录计算，产地分组的平均值不得重复计入省级比较。

追码从原始批次代码出发，按生效日顺序套用目录规则，因此后一条规则可以作用到前一条规则产生的代码上。`origin_records` 中每行保留 `source_batch`（原文代码）、`origin`（当日最终代码）和 `mapping_path`（逐条规则后的代码链）。已生效规则只改变生效日当天及之后的归属；生效日之前的历史代码保持原样，不因后来并入而回填。完整规则下本周应显示 HB-01 两天、HB-02 两天、HB-03 三天。

缺失改码规则时生效日未知，整周归属都可能被后续规则改写：`origin_weekly` 的每组标为 `attribution_status=待核`，`origin_comparison` 的 `status` 也为待核且 `origin_split_ready=false`，此时不能发布当前比较。公告与分省表齐全、两条规则齐备后，七天覆盖与产地拆分才可用于当前比较；已发布历史视图不随后续修订改变。
